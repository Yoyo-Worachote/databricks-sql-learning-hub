## ข้อ 0.2 (ปานกลาง): ตรวจโครงสร้างตาราง promotions

**โจทย์:** ตรวจสอบโครงสร้างตาราง `promotions` แล้วตอบว่าคอลัมน์ไหนเก็บวันที่ และเป็นชนิดข้อมูลอะไร

:::answer
```sql
DESCRIBE TABLE promotions;
```

| col_name | data_type | comment |
|---|---|---|
| promo_id | string | รหัสโปรโมชัน |
| product_id | string | รหัสสินค้า |
| promo_name | string | ชื่อโปรโมชัน |
| start_date | date | วันเริ่ม |
| end_date | date | วันสิ้นสุด (รวมวันนี้ด้วย) |
| discount_pct | int | เปอร์เซ็นต์ส่วนลด |

**คำตอบ:** `start_date` และ `end_date` เป็นชนิด `DATE`

**เหตุผล:** `DESCRIBE TABLE` แสดงชื่อคอลัมน์ ชนิดข้อมูล และคำอธิบาย คำอธิบายของ `end_date` บอกข้อมูลสำคัญว่า "รวมวันนี้ด้วย" จึงใช้ `BETWEEN start_date AND end_date` กรองช่วงโปรโมชันได้ถูกต้อง (เพราะเป็น DATE ไม่มีเวลา)
:::

## ข้อ 0.3 (ท้าทาย): ข้อมูลดิบพร้อมทำรายงานหรือยัง

**โจทย์:** ดูข้อมูลตาราง `sales_raw` 5 แถวแรก (เรียงตาม `raw_id`) แล้วบอกว่าทำไมตารางนี้ยังไม่พร้อมทำรายงาน

:::answer
```sql {verify}
SELECT *
FROM sales_raw
ORDER BY raw_id
LIMIT 5;
```

| raw_id | sale_date_text | store_code | amount_text |
|---|---|---|---|
| 1 | 05/01/2026 | S01 | 1,250.00 |
| 2 | 2026-01-06 | S02 | 980.50 |
| 3 | 07/01/2026 | s03 | 2,100 |
| 4 | 31/02/2026 | S01 | 450.00 |
| 5 | NULL | S04 | 700.00 |

**คำตอบ:** มีปัญหาอย่างน้อย 5 อย่าง

1. วันที่เก็บเป็นข้อความ (STRING) และรูปแบบไม่สม่ำเสมอ (`05/01/2026` กับ `2026-01-06`)
2. มีวันที่ที่ไม่มีจริง (`31/02/2026`) และวันที่ว่าง (NULL)
3. ยอดเงินเป็นข้อความ มีจุลภาคหลักพัน (`1,250.00`) และแถวอื่นมี `'N/A'`
4. รหัสสาขาตัวพิมพ์ไม่สม่ำเสมอ (`s03`) และบางแถวมีช่องว่าง (แถว 6)
5. คำนวณหรือ JOIN กับตารางอื่นโดยตรงไม่ได้ ต้องแปลงชนิดและทำความสะอาดก่อน (บทที่ 17–18)
:::
