## สูตรนี้คืออะไร

`WHERE` คือเงื่อนไขคัดแถว ระบบตรวจทีละแถว เก็บเฉพาะแถวที่เงื่อนไขเป็น **true**

**ใช้แก้ปัญหา:** ต้องการเฉพาะบางส่วนของข้อมูล เช่น สาขาเดียว ช่วงวันที่เดียว หรือยอดเกินเกณฑ์

**ใช้เมื่อ:** แทบทุก Query และควรกรองให้เร็วที่สุดเพื่อลดข้อมูลที่ต้องประมวลผล

## รูปแบบ (Syntax)

```sql
SELECT column_1, column_2
FROM table_name
WHERE column_1 = 'text_value'
  AND column_2 >= 100;
```

| ตัวเปรียบเทียบ | ความหมาย |
|---|---|
| `=` | เท่ากับ |
| `<>` หรือ `!=` | ไม่เท่ากับ |
| `>` / `>=` | มากกว่า / มากกว่าหรือเท่ากับ |
| `<` / `<=` | น้อยกว่า / น้อยกว่าหรือเท่ากับ |

## ตัวอย่างข้อมูลต้นทาง

ตาราง `sales` มี 141 แถวจาก 5 สาขา ตัวอย่างบางแถว

<!-- verify: SELECT sale_id, store_id, net_amount FROM sales WHERE sale_id IN ('T0093','T0094','T0105') ORDER BY sale_id -->
| sale_id | store_id | net_amount |
|---|---|---|
| T0093 | S05 | 51.00 |
| T0094 | S03 | 51.00 |
| T0105 | S05 | 90.00 |

## SQL Query ฉบับเต็มและผลลัพธ์

**โจทย์:** รายการขายของสาขาภูเก็ต (S05) ที่ยอดสุทธิตั้งแต่ 85 บาทขึ้นไป

```sql {verify}
SELECT
  sale_id,
  sale_date,
  store_id,
  net_amount
FROM sales
WHERE store_id = 'S05'
  AND net_amount >= 85
ORDER BY sale_id;
```

| sale_id | sale_date | store_id | net_amount |
|---|---|---|---|
| T0105 | 2026-03-04 | S05 | 90.00 |
| T0122 | 2026-03-20 | S05 | 118.00 |
| T0125 | 2026-03-22 | S05 | 150.00 |
| T0132 | 2026-03-26 | S05 | 85.00 |
| T0133 | 2026-03-28 | S05 | 90.00 |

## อธิบายทีละส่วน

| ส่วน | ความหมาย |
|---|---|
| `store_id = 'S05'` | ข้อความต้องอยู่ใน `' '` และต้องตรงตัวพิมพ์ |
| `AND` | ต้องจริงทั้งสองเงื่อนไข |
| `net_amount >= 85` | ตัวเลขไม่ต้องมี `' '` และ `>=` รวมค่า 85 (T0132 จึงติด) |

**ลำดับการทำงาน:** `FROM sales` (141 แถว) → `WHERE` เหลือ 5 แถว (S05 มี 7 แถว ตัด T0093 ยอด 51 และ T0114 ยอด 79) → `SELECT` → `ORDER BY`

## ข้อผิดพลาดที่พบบ่อย

- ลืม `' '` รอบข้อความ: `store_id = S05` ได้ Error `UNRESOLVED_COLUMN`
- ตัวพิมพ์ไม่ตรง: `payment_method = 'cash'` ได้ 0 แถว (ค่าจริงคือ `'Cash'`)
- `= NULL` ได้ 0 แถวเสมอ ต้องใช้ `IS NULL` ([ดูสูตร](#/formula/f-is-null))
- ใช้ฟังก์ชันสรุป (`SUM`, `COUNT`) ใน `WHERE` ต้องใช้ [HAVING](#/formula/f-having)

## ข้อควรระวังและกรณีพิเศษ

- เงื่อนไขกับค่า NULL ได้ผล unknown แถวนั้นจะไม่ถูกเลือก เช่น `discount_amount > 0` จะไม่เลือกแถวที่ส่วนลดเป็น NULL
- นับแถวก่อนและหลังกรองเสมอ เพื่อยืนยันว่าเงื่อนไขทำงานตามที่ตั้งใจ
- วันที่ให้เขียน `DATE'2026-02-14'` และกรองช่วงด้วย `>=` กับ `<` ([ดูสูตร](#/formula/f-date-range-filter))

## วิธีอื่นที่ใช้แทนกันได้

- หลายค่าใช้ `IN (...)` แทน `OR` หลายครั้ง ([ดูสูตร](#/formula/f-in-between-like))
- ไม่สนตัวพิมพ์ใช้ `LOWER(col) = 'cash'` หรือ `col ILIKE 'cash'`

## แบบฝึกหัด

**โจทย์:** หารายการขายที่ยอดสุทธิตั้งแต่ 300 บาทขึ้นไป เรียงยอดมากไปน้อย แล้วตาม `sale_id`

:::answer
```sql {verify}
SELECT
  sale_id,
  store_id,
  net_amount
FROM sales
WHERE net_amount >= 300
ORDER BY net_amount DESC, sale_id;
```

| sale_id | store_id | net_amount |
|---|---|---|
| T0022 | S01 | 516.00 |
| T0052 | S01 | 445.00 |
| T0058 | S01 | 435.00 |
| T0096 | S02 | 420.00 |
| T0077 | S03 | 356.00 |
| T0012 | S04 | 351.00 |
| T0136 | S01 | 351.00 |

**เหตุผล:** เงื่อนไขเดียวกับตัวเลข ใช้ `>=` เพราะ "ตั้งแต่" รวมค่า 300 และใส่ `sale_id` เป็นตัวตัดสินเพราะมี 2 รายการที่ยอด 351 เท่ากัน
:::
