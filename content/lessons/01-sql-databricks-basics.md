## SQL คืออะไร

**SQL (Structured Query Language)** คือภาษาที่ใช้ "ถามคำถาม" กับข้อมูลที่เก็บเป็นตาราง เราเขียนคำสั่งบอกว่าอยากได้ข้อมูลอะไร แล้วระบบจะไปค้นและคำนวณมาให้

คำสั่งหนึ่งชุดเรียกว่า **Query** (อ่านว่า "เควียรี" แปลว่า คำถาม/คำขอข้อมูล) เช่น

```sql
SELECT store_id, store_name
FROM stores;
```

อ่านเป็นภาษาไทยได้ว่า "ขอดูรหัสสาขาและชื่อสาขา จากตาราง stores"

ถ้าเคยใช้ Excel มาก่อน ให้เทียบแบบนี้ได้

| สิ่งที่ทำใน Excel | สิ่งที่ทำใน SQL | เรียนในบทที่ |
|---|---|---|
| ซ่อนคอลัมน์ที่ไม่ใช้ | `SELECT` เลือกคอลัมน์ | 3 |
| ใช้ Filter | `WHERE` | 4–5 |
| Sort | `ORDER BY` | 7 |
| PivotTable | `GROUP BY` + `SUM` / `COUNT` | 8–9 |
| VLOOKUP / XLOOKUP | `JOIN` | 10 |
| คัดลอกตารางมาต่อท้ายกัน | `UNION ALL` | 11 |

> [!NOTE] หลักสูตรนี้เน้น "อ่าน" ข้อมูล
> ทุกบทใช้คำสั่ง `SELECT` เพื่ออ่านและสรุปข้อมูลเท่านั้น ไม่สอนให้แก้ไขหรือลบข้อมูลจริง (`INSERT`, `UPDATE`, `DELETE`, `DROP`) คำสั่งสร้างตารางมีเฉพาะในไฟล์เตรียมชุดข้อมูลฝึก ซึ่งผู้สอนหรือทีม Data เป็นผู้รัน

## Databricks, SQL Warehouse และ SQL Editor

**Databricks** คือแพลตฟอร์มข้อมูลที่องค์กรใช้เก็บและประมวลผลข้อมูลจำนวนมาก ส่วน **Databricks SQL** คือส่วนที่ให้เราใช้ภาษา SQL ทำงานกับข้อมูลนั้น

| คำศัพท์ | ความหมาย | เปรียบเทียบ |
|---|---|---|
| **SQL Editor** | หน้าจอสำหรับพิมพ์และรัน Query | เหมือนหน้าต่างพิมพ์สูตร |
| **SQL Warehouse** | เครื่องประมวลผลที่รัน SQL ให้เรา ต้องเปิดอยู่และเรามีสิทธิ์ใช้จึงจะรันได้ | เหมือนเครื่องคิดเลขที่ต้องเปิดก่อนใช้ |
| **Catalog Explorer** | หน้าค้นหาตาราง ดูคอลัมน์ และดูข้อมูลตัวอย่าง | เหมือนสารบัญของแฟ้มเอกสาร |
| **Notebook** | อีกทางเลือกหนึ่งในการรัน SQL เป็นช่อง ๆ (Cell) | เหมือนสมุดที่แบ่งเป็นช่อง |
| **Power BI** | เครื่องมือทำ Dashboard ที่เชื่อมต่อ Databricks ผ่าน SQL Warehouse | Query ที่ตรวจแล้วใน SQL Editor คือพื้นฐานของ Dataset ใน Power BI |

> [!TIP] SQL Warehouse หยุดเองได้
> องค์กรมักตั้งให้ SQL Warehouse หยุดอัตโนมัติเมื่อไม่มีคนใช้ เพื่อประหยัดค่าใช้จ่าย ถ้าสถานะเป็น Stopped ระบบจะเริ่มให้เองเมื่อเรากดรัน อาจต้องรอ 1–3 นาที

## เริ่มต้นใช้งาน SQL Editor ทีละขั้น

:::flow
เปิด SQL Editor | เมนูด้านซ้ายของ Databricks (บาง Workspace อยู่ในกลุ่มเมนู SQL)
เลือก SQL Warehouse | Dropdown มุมขวาบน ถ้าไม่เห็นตัวเลือกเลย แปลว่ายังไม่มีสิทธิ์ ให้ติดต่อผู้ดูแลระบบ
เลือก Catalog และ Schema | Dropdown ด้านบน Editor เลือก Schema `sql_training` หรือพิมพ์ `USE sql_training;`
พิมพ์ Query | เขียนคำสั่ง SQL ในช่อง Editor
กด Run | ปุ่ม Run หรือ Ctrl+Enter (Mac: Cmd+Enter) ถ้ามีหลายคำสั่ง ให้ไฮไลต์เฉพาะคำสั่งที่ต้องการก่อน
อ่านผลลัพธ์ | ตารางผลลัพธ์แสดงด้านล่าง ดาวน์โหลดเป็น CSV/Excel ได้ตามสิทธิ์ของ Workspace
:::

> [!NOTE] ชื่อเมนูอาจต่างกันเล็กน้อย
> ตำแหน่งปุ่มและชื่อเมนูขึ้นกับเวอร์ชันและการตั้งค่า Workspace ขององค์กร หลักการยังเหมือนเดิม: เลือก Warehouse → เลือก Schema → พิมพ์ → รัน

**ถ้าองค์กรให้ใช้ Notebook แทน** ให้สร้าง Notebook ตั้งภาษาเริ่มต้นเป็น SQL แล้วเชื่อม (Attach) กับ Compute ที่มีสิทธิ์ จากนั้นวาง Query ทีละ Cell ทุกตัวอย่างในหลักสูตรนี้ใช้ได้เหมือนกัน

## Query แรกของคุณ

ก่อนเริ่ม ต้องมีชุดข้อมูลฝึกใน Schema `sql_training` (ผู้สอนหรือทีม Data สร้างให้ด้วยไฟล์ `sql/00_setup_dataset.sql` ดูรายละเอียดที่ [หน้าชุดข้อมูลฝึก](#/reference/dataset))

ลองรัน Query นี้ เพื่อดูรายชื่อสาขาทั้งหมด

```sql {verify}
SELECT *
FROM stores;
```

**ผลลัพธ์ (6 แถว)**

| store_id | store_name | province | region | store_type | open_date |
|---|---|---|---|---|---|
| S01 | สาขาสุขุมวิท | กรุงเทพฯ | Bangkok | Mall | 2019-05-01 |
| S02 | สาขาบางนา | กรุงเทพฯ | Bangkok | Mall | 2020-08-15 |
| S03 | สาขาเชียงใหม่ | เชียงใหม่ | North | Street | 2021-03-01 |
| S04 | สาขาขอนแก่น | ขอนแก่น | Northeast | Street | 2022-11-20 |
| S05 | สาขาภูเก็ต | ภูเก็ต | South | Mall | 2026-03-01 |
| S06 | สาขาหาดใหญ่ | สงขลา | South | Street | 2026-06-01 |

**อธิบายทีละส่วน**

| ส่วนของ Query | ความหมาย |
|---|---|
| `SELECT *` | ขอทุกคอลัมน์ (`*` แปลว่า ทั้งหมด) |
| `FROM stores` | จากตารางชื่อ `stores` |
| `;` | เครื่องหมายจบคำสั่ง จำเป็นเมื่อมีหลายคำสั่งในหน้าเดียว |

> [!TIP] ถ้าเจอ Error TABLE_OR_VIEW_NOT_FOUND
> แปลว่าระบบหาตารางไม่เจอ สาเหตุที่พบบ่อยคือยังไม่ได้เลือก Schema `sql_training` ให้เลือกใน Dropdown หรือเขียนชื่อเต็ม `sql_training.stores` (ดูบทที่ 22 เรื่องการแก้ Error)

## Databricks SQL ต่างจาก SQL ทั่วไปตรงไหน

SQL เป็นภาษามาตรฐาน แต่แต่ละระบบ (เรียกว่า **Dialect** หรือ "สำเนียง") มีรายละเอียดต่างกัน ถ้าค้นตัวอย่างจากอินเทอร์เน็ต ให้ตรวจก่อนว่าเป็นของ Databricks / Spark SQL หรือไม่ ตัวอย่างความต่างที่จะเจอในหลักสูตร

| เรื่อง | Databricks SQL | SQL Server (ตัวอย่างระบบอื่น) |
|---|---|---|
| จำกัดจำนวนแถว | `LIMIT 10` ท้าย Query | `SELECT TOP 10 ...` |
| ชื่อคอลัมน์ที่มีช่องว่าง | `` `ชื่อ คอลัมน์` `` (Backtick) | `[ชื่อ คอลัมน์]` |
| หาร `5 / 2` | ได้ `2.5` | ได้ `2` เมื่อเป็นจำนวนเต็ม |
| หารด้วยศูนย์ | Error `DIVIDE_BY_ZERO` (ANSI mode ค่าเริ่มต้น) | Error |
| กรองผล Window Function | มี `QUALIFY` | ไม่มี ต้องใช้ CTE |

> [!DATABRICKS] ANSI mode
> SQL Warehouse ของ Databricks เปิด **ANSI mode** เป็นค่าเริ่มต้น ทำให้การหารด้วยศูนย์หรือแปลงชนิดข้อมูลไม่ได้เกิด Error แทนที่จะได้ค่าแปลก ๆ อย่างเงียบ ๆ ซึ่งช่วยให้เราเจอปัญหาเร็วขึ้น เราจะเรียนวิธีรับมือในบทที่ 8 และ 18

ดูตารางเปรียบเทียบฉบับเต็มได้ที่ [Databricks SQL ต่างจาก SQL อื่นอย่างไร](#/reference/dialects)

## ทำงานกับข้อมูลอย่างปลอดภัย

- ใช้ `SELECT` เพื่ออ่านข้อมูล ไม่รันคำสั่งแก้ไขหรือลบข้อมูลในระบบงานจริงโดยไม่ได้รับอนุญาต
- ดูข้อมูลตัวอย่างด้วย `LIMIT` ก่อนเสมอ โดยเฉพาะตารางใหญ่ เพื่อไม่ให้รันนานและเปลืองทรัพยากร
- ไม่ดาวน์โหลดหรือส่งต่อข้อมูลลูกค้าหรือข้อมูลภายในออกนอกช่องทางที่องค์กรอนุญาต
- ชุดข้อมูลฝึกในหลักสูตรนี้เป็น **ข้อมูลจำลองทั้งหมด** ฝึกได้อย่างสบายใจ

## สรุปและตรวจความเข้าใจ

- **SQL** คือภาษาถามข้อมูล คำสั่งหนึ่งชุดเรียกว่า **Query**
- รัน Query ใน **SQL Editor** โดยต้องเลือก **SQL Warehouse** และ Schema ก่อน
- Databricks SQL มีรายละเอียดบางอย่างต่างจาก SQL ระบบอื่น ต้องตรวจก่อนนำตัวอย่างจากที่อื่นมาใช้

> [!CHECK] ลองตอบ
> 1. ถ้ากด Run แล้วระบบหมุนรอนานในครั้งแรกของวัน น่าจะเกิดจากอะไร
> 2. Query `SELECT * FROM stores;` คืนข้อมูลกี่แถวและกี่คอลัมน์

:::answer ดูคำตอบ
1. SQL Warehouse อาจหยุดอยู่ (Stopped) ระบบกำลังเริ่มเครื่องให้ ซึ่งใช้เวลาประมาณ 1–3 นาที
2. ได้ 6 แถว (6 สาขา) และ 6 คอลัมน์ คือ `store_id`, `store_name`, `province`, `region`, `store_type`, `open_date`
:::
