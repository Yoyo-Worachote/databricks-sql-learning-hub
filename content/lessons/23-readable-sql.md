## ทำไมต้องเขียน SQL ให้อ่านง่าย

Query ในงานจริงถูกอ่านมากกว่าถูกเขียน: เพื่อนร่วมทีมต้องตรวจ ทีม BI ต้องนำไปใช้ต่อ และตัวเราเองต้องกลับมาแก้ในอีก 3 เดือน Query ที่อ่านง่ายช่วยให้

- หาจุดผิดได้เร็ว เพราะเห็นโครงสร้างชัด
- ตรวจ Logic ทางธุรกิจได้ (เช่น ตัดรายการอะไรออกบ้าง)
- ส่งต่องานได้โดยไม่ต้องอธิบายด้วยปาก

## Before / After: Query เดียวกัน เขียนสองแบบ

**แบบอ่านยาก** (รันได้และผลถูก แต่ต้องใช้เวลาอ่านนาน)

```sql {verify}
select s.store_id,st.store_name,sum(s.net_amount) t,count(*) c from sales s left join stores st on s.store_id=st.store_id where s.quantity between 1 and 50 group by s.store_id,st.store_name having sum(s.net_amount)>2000 order by t desc
```

| store_id | store_name | t | c |
|---|---|---|---|
| S01 | สาขาสุขุมวิท | 4378.00 | 46 |
| S02 | สาขาบางนา | 2810.00 | 36 |
| S04 | สาขาขอนแก่น | 2618.00 | 27 |

**แบบอ่านง่าย** ผลลัพธ์เหมือนเดิมทุกตัวเลข

```sql {verify}
-- รายงาน: สาขาที่ยอดขายรายการปกติเกิน 2,000 บาท (ไตรมาส 1 ปี 2026)
-- Grain: 1 แถว = 1 สาขา
-- หมายเหตุ: ตัดรายการรับคืนและรายการผิดปกติ (quantity นอกช่วง 1-50) ออก
WITH normal_sales AS (
  SELECT
    store_id,
    net_amount
  FROM sales
  WHERE quantity BETWEEN 1 AND 50
),
store_summary AS (
  SELECT
    ns.store_id,
    st.store_name,
    SUM(ns.net_amount) AS total_net,
    COUNT(*)           AS line_count
  FROM normal_sales AS ns
  LEFT JOIN stores AS st
    ON ns.store_id = st.store_id
  GROUP BY
    ns.store_id,
    st.store_name
)
SELECT
  store_id,
  store_name,
  total_net,
  line_count
FROM store_summary
WHERE total_net > 2000
ORDER BY total_net DESC;
```

| store_id | store_name | total_net | line_count |
|---|---|---|---|
| S01 | สาขาสุขุมวิท | 4378.00 | 46 |
| S02 | สาขาบางนา | 2810.00 | 36 |
| S04 | สาขาขอนแก่น | 2618.00 | 27 |

**สิ่งที่ปรับ**

| ก่อน | หลัง | เหตุผล |
|---|---|---|
| ทุกอย่างอยู่บรรทัดเดียว | 1 Clause ต่อบรรทัด 1 คอลัมน์ต่อบรรทัด | อ่านและเพิ่ม/ลบคอลัมน์ง่าย |
| `select`, `from` ตัวเล็กปนชื่อคอลัมน์ | คำสั่ง SQL ตัวพิมพ์ใหญ่ | แยกคำสั่งออกจากชื่อข้อมูลได้ทันที |
| Alias `t`, `c` | `total_net`, `line_count` | รู้ความหมายโดยไม่ต้องย้อนอ่าน |
| เงื่อนไขทำความสะอาดปนกับการสรุป | แยกเป็น CTE `normal_sales` | เห็นว่าตัดอะไรออกและนำไปใช้ซ้ำได้ |
| ไม่มีคำอธิบาย | Comment บอกวัตถุประสงค์ Grain และเงื่อนไข | คนอื่นรู้ว่า Query นี้ตอบคำถามอะไร |

> [!NOTE] ตัวเลขนี้ไม่ใช่ clean sales
> Query นี้ไม่ได้ตัดแถวซ้ำ T0042 ยอด S01 จึงเป็น 4,378 (มากกว่ายอด clean 4,363 อยู่ 15 บาท) Comment ที่ดีช่วยให้ผู้อ่านรู้ทันทีว่าตัวเลขนี้ใช้นิยามอะไร

## มาตรฐานการจัดรูปแบบที่แนะนำ

1. **คำสั่ง SQL เป็นตัวพิมพ์ใหญ่** (`SELECT`, `FROM`, `WHERE`) ชื่อตาราง/คอลัมน์ตัวพิมพ์เล็ก
2. **1 Clause ต่อ 1 บรรทัด** และ **1 คอลัมน์ต่อ 1 บรรทัด** เมื่อมีหลายคอลัมน์
3. **เยื้อง 2 ช่อง** (หรือ 4 ช่อง แต่ใช้ให้เหมือนกันทั้งทีม) สำหรับรายการภายใต้ Clause
4. **จัด `AS` ให้ตรงกัน** เมื่อคอลัมน์คำนวณยาว เพื่อให้กวาดตาอ่านชื่อผลลัพธ์ได้
5. **ใส่ `AS` ทุกครั้ง** ทั้ง Alias ของตารางและคอลัมน์ (ถึง SQL จะยอมให้ละได้ก็ตาม)
6. **ใส่ชื่อย่อตารางนำหน้าทุกคอลัมน์** เมื่อมีมากกว่า 1 ตาราง
7. **เงื่อนไข JOIN อยู่ใน `ON`** เงื่อนไขกรองอยู่ใน `WHERE` แยกให้ชัด
8. **ใส่ `;` ครั้งเดียว** ท้ายคำสั่ง

## การตั้งชื่อ

| สิ่งที่ตั้งชื่อ | แนวทาง | ตัวอย่างที่ดี | ตัวอย่างที่ควรเลี่ยง |
|---|---|---|---|
| คอลัมน์ผลลัพธ์ | snake_case ภาษาอังกฤษ บอกความหมายและหน่วย | `net_sales`, `gp_pct`, `price_thb` | `x`, `total1`, `ยอด` |
| CTE | บอกว่าขั้นนี้ได้ข้อมูลอะไร | `clean_sales`, `store_monthly_sales`, `ranked_products` | `t1`, `temp`, `cte2` |
| Alias ตาราง | ตัวย่อที่จำง่ายและสม่ำเสมอ | `s` = sales, `p` = products, `st` = stores | `a`, `b`, `c` |
| คอลัมน์อันดับ | บอกประเภทอันดับ | `rn`, `sales_rank`, `price_rank_in_category` | `r` |
| คอลัมน์ธง | ขึ้นต้นด้วย `is_` / `has_` หรือ `_flag` | `is_return`, `dq_flag` | `f` |

## เขียน Comment ให้มีประโยชน์

**ควรเขียน:** สิ่งที่โค้ดไม่ได้บอก

- วัตถุประสงค์ของ Query และผู้ใช้รายงาน
- **Grain** ของผลลัพธ์ (1 แถว = อะไร)
- เหตุผลทางธุรกิจของเงื่อนไข เช่น "ตัด quantity ≤ 0 เพราะเป็นรายการรับคืน รายงานแยกต่างหาก"
- ข้อจำกัดหรือข้อสังเกต เช่น "P099 ไม่มีต้นทุน ไม่นับในกำไร"

**ไม่ต้องเขียน:** สิ่งที่โค้ดบอกอยู่แล้ว เช่น `-- เลือกคอลัมน์ store_id` หรือ `-- รวมยอด`

**ตัวอย่างหัว Query สำหรับงานที่ส่งต่อ**

```sql
-- =====================================================================
-- ชื่อรายงาน : ยอดขายรายเดือนต่อสาขา (Q1 2026)
-- ผู้ใช้     : ทีมขาย / Dashboard ยอดขายรายเดือน
-- Grain      : 1 แถว = 1 เดือน x 1 สาขา
-- แหล่งข้อมูล: sql_training.sales, sql_training.stores
-- นิยาม      : clean sales = ตัดแถวซ้ำ และ quantity 1-50
-- ปรับปรุง   : 2026-04-05 เพิ่มคอลัมน์ line_count
-- =====================================================================
```

## แบ่ง Query เป็นขั้นด้วย CTE

- **1 CTE = 1 ความคิด** เช่น ทำความสะอาด → สรุป → จัดอันดับ → เลือกผลลัพธ์
- เรียงจาก**ข้อมูลดิบ**ไปหา**ผลลัพธ์** ให้อ่านจากบนลงล่างได้
- ทำความสะอาดข้อมูล**ครั้งเดียว**ใน CTE แรก แล้วทุกขั้นถัดไปใช้ร่วมกัน ไม่คัดลอกเงื่อนไขซ้ำหลายจุด
- `ORDER BY` ใส่ที่ `SELECT` สุดท้ายเท่านั้น
- ถ้า Subquery ซ้อนเกิน 1 ชั้น ให้เปลี่ยนเป็น CTE

## เช็กลิสต์ก่อนส่ง Query ให้คนอื่น

- [ ] รันผ่าน และผลลัพธ์ตรงกับที่ตั้งใจ (ตรวจจำนวนแถวและยอดรวมแล้ว)
- [ ] มี Comment บอกวัตถุประสงค์และ Grain
- [ ] ไม่มี `SELECT *` ในผลลัพธ์สุดท้าย
- [ ] ชื่อคอลัมน์และ CTE สื่อความหมาย
- [ ] ทุกคอลัมน์มีชื่อย่อตารางนำหน้าเมื่อมีหลายตาราง
- [ ] `ROW_NUMBER` และ `LIMIT` มีตัวตัดสินใน `ORDER BY`
- [ ] การหารใช้ `NULLIF` หรือ `try_divide`
- [ ] ไม่มีข้อมูลส่วนบุคคลหรือรหัสผ่านอยู่ใน Query หรือ Comment

> [!TIP] ใช้ตัวจัดรูปแบบอัตโนมัติ
> SQL Editor ของ Databricks มีคำสั่ง Format Query (ดูในเมนูของ Editor หรือคลิกขวา) ช่วยจัดรูปแบบเบื้องต้นได้ แต่การตั้งชื่อ การแบ่ง CTE และ Comment ยังต้องคิดเอง

## ฝึกทำ

**โจทย์:** ปรับ Query ด้านล่างให้อ่านง่ายตามมาตรฐาน (ผลลัพธ์ต้องเหมือนเดิม)

```sql {run}
select p.category c,count(distinct s.customer_id) n from sales s join products p on s.product_id=p.product_id where s.customer_id is not null group by p.category order by n desc
```

| c | n |
|---|---|
| Beverage | 19 |
| Snack | 16 |
| Personal Care | 16 |
| NULL | 6 |

(Snack กับ Personal Care มีค่าเท่ากัน ลำดับของสองแถวนี้อาจสลับกันได้ในแต่ละครั้งที่รัน)

:::answer ดูเฉลยและคำอธิบาย
```sql {verify}
-- จำนวนลูกค้าสมาชิก (ไม่ซ้ำ) ที่ซื้อสินค้าแต่ละหมวด
-- Grain: 1 แถว = 1 หมวดสินค้า
-- หมายเหตุ: INNER JOIN จึงไม่รวมรายการ P099 ที่ไม่มีในตารางสินค้า
SELECT
  COALESCE(p.category, 'Unknown') AS category,
  COUNT(DISTINCT s.customer_id)   AS member_count
FROM sales AS s
INNER JOIN products AS p
  ON s.product_id = p.product_id
WHERE s.customer_id IS NOT NULL
GROUP BY COALESCE(p.category, 'Unknown')
ORDER BY member_count DESC, category;
```

| category | member_count |
|---|---|
| Beverage | 19 |
| Personal Care | 16 |
| Snack | 16 |
| Unknown | 6 |

**สิ่งที่ปรับ:** ตั้งชื่อคอลัมน์ให้สื่อความหมาย (`c` → `category`, `n` → `member_count`) ใส่ `AS` และ `INNER JOIN` ชัดเจน จัดบรรทัด เติม `'Unknown'` แทน NULL เพื่อให้อ่านรายงานง่าย เพิ่มตัวตัดสินใน `ORDER BY` (Snack กับ Personal Care มีลูกค้า 16 คนเท่ากัน จึงเรียงตามชื่อหมวดให้ผลคงที่) และเขียน Comment บอกวัตถุประสงค์ Grain และข้อจำกัด ตัวเลขทุกตัวเหมือนเดิม
:::
