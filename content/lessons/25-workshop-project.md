## วิธีคิด 6 ขั้น: จากคำถามธุรกิจสู่ Query ที่ตรวจสอบได้

งานจริงไม่ได้บอกว่า "ให้ใช้ LEFT JOIN" แต่จะมาเป็นคำถาม เช่น "เดือนนี้ภาคไหนขายดี" ใช้ 6 ขั้นนี้ทุกครั้งก่อนเริ่มพิมพ์

:::flow
ผู้ถามต้องการตัดสินใจเรื่องอะไร | เข้าใจเป้าหมาย จะได้รู้ว่าต้องละเอียดแค่ไหน และตัวเลขไหนสำคัญ
ข้อมูลอยู่ตารางไหน | ระบุตารางและคอลัมน์ที่ต้องใช้ ตรวจด้วย DESCRIBE
ผลลัพธ์ 1 แถวคืออะไร (Grain) | เช่น 1 แถว = 1 ภูมิภาค หรือ 1 สาขา x 1 เดือน
กรองอะไรบ้าง | ช่วงเวลา สาขา และนิยามข้อมูลสะอาด
สรุปอย่างไร | SUM / COUNT / อันดับ / สัดส่วน / เทียบช่วงเวลา
ตรวจตัวเลขอย่างไร | จำนวนแถว ยอดรวมเทียบต้นทาง ตัวอย่างบางแถวคำนวณมือ
:::

## ตัวอย่างเต็ม: ยอดขายรายภูมิภาคเดือนมีนาคม

**คำถาม:** หัวหน้าฝ่ายขายถาม "เดือนมีนาคม 2026 แต่ละภูมิภาคขายได้เท่าไร คิดเป็นกี่ % ของบริษัท และสาขาไหนทำยอดสูงสุดในภูมิภาค" (ใช้ข้อมูลที่ทำความสะอาดแล้ว)

**คิดตาม 6 ขั้น**

| ขั้น | คำตอบ |
|---|---|
| 1. ตัดสินใจเรื่องอะไร | จัดสรรงบโปรโมชันให้แต่ละภูมิภาค |
| 2. ตารางไหน | `sales` (ยอดขาย), `stores` (ภูมิภาคและชื่อสาขา) |
| 3. Grain | 1 แถว = 1 ภูมิภาค |
| 4. กรองอะไร | เดือนมีนาคม 2026, clean sales (ตัดซ้ำ + quantity 1–50) |
| 5. สรุปอย่างไร | SUM ต่อภูมิภาค, % ต่อยอดรวม, อันดับ 1 ของสาขาในภูมิภาค |
| 6. ตรวจอย่างไร | ผลรวมทุกภูมิภาค = ยอด clean ของเดือนมีนาคม, % รวม ≈ 100 |

```sql {verify}
-- ยอดขายรายภูมิภาค เดือนมีนาคม 2026 (clean sales)
-- Grain: 1 แถว = 1 ภูมิภาค
WITH clean_sales AS (
  SELECT DISTINCT *
  FROM sales
  WHERE quantity BETWEEN 1 AND 50
    AND sale_date >= DATE'2026-03-01'
    AND sale_date <  DATE'2026-04-01'
),
store_sales AS (
  -- 1 แถว = 1 สาขา
  SELECT
    st.region,
    st.store_name,
    SUM(c.net_amount) AS store_net
  FROM clean_sales AS c
  JOIN stores AS st
    ON c.store_id = st.store_id
  GROUP BY st.region, st.store_name
),
region_sales AS (
  -- 1 แถว = 1 ภูมิภาค
  SELECT
    region,
    SUM(store_net) AS region_net,
    COUNT(*)       AS store_count
  FROM store_sales
  GROUP BY region
),
top_store AS (
  -- อันดับสาขาภายในภูมิภาค
  SELECT
    region,
    store_name,
    store_net,
    ROW_NUMBER() OVER (PARTITION BY region ORDER BY store_net DESC, store_name) AS rn
  FROM store_sales
)
SELECT
  r.region,
  r.store_count,
  r.region_net,
  ROUND(r.region_net * 100.0 / SUM(r.region_net) OVER (), 1) AS share_pct,
  t.store_name                                               AS top_store,
  t.store_net                                                AS top_store_net
FROM region_sales AS r
JOIN top_store AS t
  ON  r.region = t.region
  AND t.rn = 1
ORDER BY r.region_net DESC;
```

| region | store_count | region_net | share_pct | top_store | top_store_net |
|---|---|---|---|---|---|
| Bangkok | 2 | 2613.00 | 56.0 | สาขาบางนา | 1328.00 |
| Northeast | 1 | 972.00 | 20.8 | สาขาขอนแก่น | 972.00 |
| South | 1 | 663.00 | 14.2 | สาขาภูเก็ต | 663.00 |
| North | 1 | 418.00 | 9.0 | สาขาเชียงใหม่ | 418.00 |

**ขั้นตรวจสอบ (ข้อ 6)**

```sql {verify}
SELECT
  COUNT(*)        AS clean_rows,
  SUM(net_amount) AS clean_net
FROM (
  SELECT DISTINCT *
  FROM sales
  WHERE quantity BETWEEN 1 AND 50
    AND sale_date >= DATE'2026-03-01'
    AND sale_date <  DATE'2026-04-01'
) AS c;
```

| clean_rows | clean_net |
|---|---|
| 50 | 4666.00 |

ผลรวมทุกภูมิภาค 2,613 + 972 + 663 + 418 = 4,666 ตรงกับยอด clean ของเดือนมีนาคม และ % รวม 56.0 + 20.8 + 14.2 + 9.0 = 100.0

**สื่อสารผล:** "เดือนมีนาคม กรุงเทพฯ ทำยอด 56% ของบริษัท นำโดยสาขาบางนา (1,328 บาท) ภาคใต้มีเพียงสาขาภูเก็ตที่เพิ่งเปิดเดือนนี้ ยังทำได้ 14% ตัวเลขนี้ตัดรายการซื้อ 60 ชิ้นของสาขาบางนา (420 บาท) ออกแล้ว"

> [!TIP] เทคนิคที่ใช้ในตัวอย่างนี้มาจากบทไหน
> CTE (บทที่ 12), JOIN (บทที่ 10), GROUP BY (บทที่ 9), ROW_NUMBER + PARTITION BY (บทที่ 15–16), SUM() OVER () (บทที่ 14), clean sales (บทที่ 19) งานจริงคือการประกอบเทคนิคพื้นฐานเข้าด้วยกันอย่างเป็นขั้นตอน
