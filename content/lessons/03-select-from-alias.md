## SELECT และ FROM คืออะไร

Query ที่ง่ายที่สุดมีแค่ 2 ส่วน

- `SELECT` = "อยากเห็น**คอลัมน์อะไร**"
- `FROM` = "เอามาจาก**ตารางไหน**"

**รูปแบบ (Syntax)**

```sql
SELECT
  column_1,
  column_2 AS new_name,
  column_3 * column_4 AS calculated_column
FROM table_name;
```

คำที่เป็น `column_1`, `table_name` ให้แทนด้วยชื่อจริงจากตาราง

> [!TIP] เขียนอย่างไรให้อ่านง่าย
> SQL ไม่สนใจการขึ้นบรรทัดหรือเว้นวรรค และไม่สนตัวพิมพ์เล็ก/ใหญ่ของคำสั่ง (`select` = `SELECT`) แต่นิยมเขียนคำสั่งเป็นตัวพิมพ์ใหญ่ และเขียน **1 คอลัมน์ต่อ 1 บรรทัด** เพื่อให้อ่านและแก้ง่าย

## เลือกเฉพาะคอลัมน์ที่ต้องการ

**สถานการณ์:** ฝ่ายจัดซื้อขอรายชื่อสินค้าพร้อมราคาป้าย โดยไม่ต้องการข้อมูลอื่น

**ข้อมูลต้นทาง** ตาราง `products` มี 8 คอลัมน์: `product_id`, `product_name`, `category`, `brand`, `unit_cost`, `list_price`, `launch_date`, `is_active`

```sql {verify partial}
SELECT
  product_id,
  product_name,
  list_price
FROM products;
```

**ผลลัพธ์** (แสดง 6 จาก 12 แถว)

| product_id | product_name | list_price |
|---|---|---|
| P001 | น้ำดื่ม 600ml | 7.00 |
| P002 | ชาเขียว 500ml | 20.00 |
| P003 | กาแฟกระป๋อง 180ml | 18.00 |
| P004 | มันฝรั่งทอด 50g | 25.00 |
| P005 | ขนมปังกรอบ 60g | 15.00 |
| P006 | ถั่วอบเกลือ 40g | 30.00 |

**อธิบายทีละส่วน**

| ส่วนของ Query | ความหมาย |
|---|---|
| `SELECT` | เริ่มบอกว่าจะแสดงคอลัมน์ไหน |
| `product_id, product_name, list_price` | รายชื่อคอลัมน์ คั่นด้วยจุลภาค `,` ลำดับในผลลัพธ์เป็นไปตามที่เขียน |
| `FROM products` | อ่านจากตาราง `products` |

**ทำไมไม่ใช้ `SELECT *` ตลอด** การระบุคอลัมน์ทำให้ Query เร็วขึ้น (อ่านข้อมูลน้อยลง) อ่านง่ายขึ้น และไม่พังเมื่อตารางต้นทางเพิ่มคอลัมน์ใหม่

| | `SELECT *` | ระบุคอลัมน์ |
|---|---|---|
| จำนวนคอลัมน์ที่ได้จาก `sales` | 11 คอลัมน์ รวมที่ไม่ได้ใช้ | เฉพาะที่รายงานต้องการ |
| ความเร็วกับตารางใหญ่ | ช้ากว่า | เร็วกว่า |
| เหมาะกับ | สำรวจตารางเล็ก | งานจริงและรายงาน |

## ตั้งชื่อคอลัมน์ด้วย AS (Column Alias)

**Alias** (อ่านว่า "เอ-ลี-แอส") แปลว่า **ชื่อเล่น** ใช้ตั้งชื่อคอลัมน์ในผลลัพธ์ให้อ่านเข้าใจง่าย โดย**ไม่ได้เปลี่ยนชื่อในตารางจริง**

```sql {verify partial}
SELECT
  product_name AS product,
  list_price   AS price_thb
FROM products;
```

**ผลลัพธ์** (แสดง 4 จาก 12 แถว)

| product | price_thb |
|---|---|
| น้ำดื่ม 600ml | 7.00 |
| ชาเขียว 500ml | 20.00 |
| กาแฟกระป๋อง 180ml | 18.00 |
| มันฝรั่งทอด 50g | 25.00 |

- `product_name AS product` แสดงคอลัมน์ `product_name` ในชื่อ `product`
- `AS price_thb` ชื่อที่บอกทั้งความหมายและหน่วย คนอ่านรายงานเข้าใจทันที

> [!TIP] หลักการตั้งชื่อ
> ใช้ภาษาอังกฤษตัวพิมพ์เล็ก คั่นคำด้วย `_` (เรียกว่า snake_case) เช่น `net_sales`, `price_thb` เพราะนำไปใช้ต่อใน Power BI / Excel ได้ง่าย ถ้าจำเป็นต้องใช้ชื่อภาษาไทยหรือมีช่องว่าง ให้ครอบด้วย Backtick เช่น ``AS `ราคา (บาท)` ``

> [!DATABRICKS] Backtick ไม่ใช่วงเล็บเหลี่ยม
> Databricks ใช้ Backtick `` ` ` `` ครอบชื่อที่มีช่องว่าง ส่วน SQL Server ใช้ `[ ]` และมาตรฐาน ANSI ใช้ `" "` ถ้าคัดลอกตัวอย่างจากระบบอื่นต้องเปลี่ยนก่อน

## สร้างคอลัมน์คำนวณ

คำนวณค่าใหม่จากคอลัมน์ที่มีอยู่ได้ด้วย `+ - * /` ระบบคำนวณ**ทีละแถว**

**สถานการณ์:** อยากรู้กำไรต่อชิ้นของสินค้าแต่ละตัว = ราคาป้าย − ต้นทุน

```sql {verify}
SELECT
  product_name,
  list_price,
  unit_cost,
  list_price - unit_cost AS margin_per_unit
FROM products
LIMIT 5;
```

**ผลลัพธ์ (5 แถว)**

| product_name | list_price | unit_cost | margin_per_unit |
|---|---|---|---|
| น้ำดื่ม 600ml | 7.00 | 4.50 | 2.50 |
| ชาเขียว 500ml | 20.00 | 12.00 | 8.00 |
| กาแฟกระป๋อง 180ml | 18.00 | 10.00 | 8.00 |
| มันฝรั่งทอด 50g | 25.00 | 15.00 | 10.00 |
| ขนมปังกรอบ 60g | 15.00 | 8.00 | 7.00 |

**ดูการคำนวณของแถวแรก:** 7.00 − 4.50 = 2.50

> [!NOTE] คอลัมน์คำนวณไม่ได้บันทึกลงตาราง
> `margin_per_unit` มีอยู่เฉพาะในผลลัพธ์ของ Query นี้เท่านั้น ตาราง `products` ไม่ได้เปลี่ยนแปลง

`LIMIT 5` ช่วยให้ดูแค่ไม่กี่แถวเพื่อตรวจว่าสูตรถูกก่อนรันทั้งตาราง (ตารางนี้ไม่มี `ORDER BY` จึงไม่รับประกันว่าได้ 5 แถวไหน)

## ชื่อย่อของตาราง (Table Alias)

นอกจากตั้งชื่อคอลัมน์ เรายังตั้งชื่อย่อให้**ตาราง**ได้ด้วย แล้วใช้ชื่อย่อนำหน้าคอลัมน์ เช่น `p.product_name` ซึ่งจะจำเป็นมากเมื่อใช้หลายตาราง (บทที่ 10)

```sql {verify partial}
SELECT
  p.product_id,
  p.product_name
FROM products AS p;
```

| product_id | product_name |
|---|---|
| P001 | น้ำดื่ม 600ml |
| P002 | ชาเขียว 500ml |

- `FROM products AS p` ตั้งชื่อย่อตาราง `products` ว่า `p`
- `p.product_id` = คอลัมน์ `product_id` ของตาราง `p`
- ตั้งชื่อย่อให้สื่อความหมาย เช่น `s` = sales, `p` = products, `st` = stores หลีกเลี่ยง `a`, `b`, `t1` ใน Query ยาว

## ข้อผิดพลาดที่พบบ่อย

> [!MISTAKE] ลืมจุลภาคระหว่างคอลัมน์
> Query ด้านล่าง**ไม่ Error** แต่ได้ผลผิด

```sql {verify}
SELECT
  product_name
  product_id
FROM products
LIMIT 3;
```

| product_id |
|---|
| น้ำดื่ม 600ml |
| ชาเขียว 500ml |
| กาแฟกระป๋อง 180ml |

ได้คอลัมน์เดียวชื่อ `product_id` แต่ข้างในเป็นชื่อสินค้า เพราะ SQL ตีความว่า `product_id` คือ**ชื่อเล่น (Alias)** ของ `product_name` (คำว่า `AS` ละได้) วิธีแก้คือใส่จุลภาค

```sql {verify}
SELECT
  product_name,
  product_id
FROM products
LIMIT 3;
```

| product_name | product_id |
|---|---|
| น้ำดื่ม 600ml | P001 |
| ชาเขียว 500ml | P002 |
| กาแฟกระป๋อง 180ml | P003 |

> [!MISTAKE] ใส่ชื่อคอลัมน์ในเครื่องหมาย ' '
> `SELECT 'product_name' FROM products LIMIT 3;` ได้คำว่า `product_name` ซ้ำทุกแถว เพราะ `' '` คือ**ข้อความ (String)** ไม่ใช่ชื่อคอลัมน์ ให้เขียนชื่อคอลัมน์ตรง ๆ หรือใช้ Backtick ถ้ามีอักขระพิเศษ

**ข้อผิดพลาดอื่น ๆ**

- ใส่จุลภาคเกินหลังคอลัมน์สุดท้ายก่อน `FROM` จะเกิด `PARSE_SYNTAX_ERROR`
- สะกดชื่อคอลัมน์ผิด จะเกิด `UNRESOLVED_COLUMN` ให้ใช้ `DESCRIBE TABLE` ตรวจชื่อ
- เข้าใจว่า `AS` เปลี่ยนชื่อคอลัมน์ในตารางจริง

> [!KEY] หลักจำ
> ตรวจจำนวนคอลัมน์ในผลลัพธ์ทุกครั้งว่าตรงกับที่เขียน และใส่จุลภาคระหว่างทุกคอลัมน์

## ฝึกทำ

**โจทย์:** แสดง `sale_id`, `quantity`, `unit_price` และยอดก่อนหักส่วนลด (`quantity * unit_price`) ตั้งชื่อว่า `gross_amount` เรียงตาม `sale_id` เพียง 3 แถว

:::answer ดูเฉลยและคำอธิบาย
```sql {verify}
SELECT
  sale_id,
  quantity,
  unit_price,
  quantity * unit_price AS gross_amount
FROM sales
ORDER BY sale_id
LIMIT 3;
```

| sale_id | quantity | unit_price | gross_amount |
|---|---|---|---|
| T0001 | 1 | 18.00 | 18.00 |
| T0002 | 1 | 18.00 | 18.00 |
| T0003 | 5 | 18.00 | 90.00 |

**เหตุผล:** คอลัมน์คำนวณ `quantity * unit_price` ทำทีละแถว (แถว T0003: 5 × 18.00 = 90.00) และใส่ `ORDER BY sale_id` เพื่อให้ได้ 3 แถวเดิมทุกครั้งที่รัน (เรียนละเอียดในบทที่ 7)
:::
