## DISTINCT: ดูว่ามีค่าอะไรบ้าง

`SELECT DISTINCT` ตัด**แถวที่ซ้ำกันทั้งแถว**ออกจากผลลัพธ์ เหลือแต่ละค่าเพียงครั้งเดียว ใช้บ่อยตอนสำรวจข้อมูลก่อนเขียนเงื่อนไข

**สถานการณ์:** ฝ่ายจัดซื้ออยากรู้ว่ามีหมวดสินค้าอะไรบ้าง

```sql {verify}
SELECT DISTINCT
  category
FROM products
ORDER BY category;
```

| category |
|---|
| NULL |
| Beverage |
| Household |
| Personal Care |
| Snack |

ตาราง `products` มี 12 แถว แต่มีหมวดที่ไม่ซ้ำเพียง 5 ค่า (นับ `NULL` เป็น 1 ค่าด้วย เพราะมีสินค้าที่ยังไม่กำหนดหมวด)

## DISTINCT หลายคอลัมน์

ถ้าเลือกหลายคอลัมน์ DISTINCT จะดูความซ้ำจาก**ทุกคอลัมน์รวมกัน** (ไม่ใช่แค่คอลัมน์แรก)

```sql {verify}
SELECT DISTINCT
  store_id,
  payment_method
FROM sales
ORDER BY store_id, payment_method;
```

**ผลลัพธ์ (14 แถว)**

| store_id | payment_method |
|---|---|
| S01 | Cash |
| S01 | Credit Card |
| S01 | QR Payment |
| S02 | Cash |
| S02 | Credit Card |
| S02 | QR Payment |
| S03 | Cash |
| S03 | Credit Card |
| S03 | QR Payment |
| S04 | Cash |
| S04 | Credit Card |
| S04 | QR Payment |
| S05 | Cash |
| S05 | Credit Card |

ได้ 14 คู่ (สาขา, วิธีชำระ) ที่เกิดขึ้นจริง ถ้า `SELECT DISTINCT store_id` อย่างเดียวจะได้ 5 แถว สังเกตว่า S05 ไม่มี QR Payment

> [!WARNING] อย่าใช้ DISTINCT ปิดปัญหาข้อมูลซ้ำ
> ถ้าผลลัพธ์มีแถวซ้ำโดยไม่คาดคิด (เช่น หลัง JOIN) ให้หาสาเหตุก่อน การใส่ DISTINCT อาจซ่อนปัญหาและทำให้ยอดรวมผิดโดยไม่รู้ตัว (บทที่ 10 และ 19)

## ORDER BY: เรียงลำดับผลลัพธ์

ตารางในฐานข้อมูล**ไม่มีลำดับแถวที่แน่นอน** ถ้าต้องการลำดับต้องเขียน `ORDER BY` เสมอ

| คำสั่ง | ความหมาย |
|---|---|
| `ORDER BY col` หรือ `ORDER BY col ASC` | น้อยไปมาก (ค่าเริ่มต้น) A→Z, 1→9, วันเก่า→ใหม่ |
| `ORDER BY col DESC` | มากไปน้อย Z→A, 9→1, วันใหม่→เก่า |
| `ORDER BY a, b DESC` | เรียงตาม `a` ก่อน ถ้า `a` เท่ากันจึงเรียงตาม `b` |

```sql {verify partial}
SELECT
  product_name,
  list_price
FROM products
ORDER BY list_price DESC;
```

**ผลลัพธ์** (แสดง 5 จาก 12 แถว)

| product_name | list_price |
|---|---|
| แชมพู 400ml | 129.00 |
| กระดาษทิชชู 6 ม้วน | 99.00 |
| สบู่เหลว 450ml | 89.00 |
| ยาสีฟัน 160g | 59.00 |
| ถุงขยะ 30 ใบ | 49.00 |

## เรียงหลายคอลัมน์และกำหนดตำแหน่ง NULL

**สถานการณ์:** อยากเห็นสินค้าจัดตามหมวด (A→Z) ภายในหมวดเรียงราคาจากแพงไปถูก และให้สินค้าที่ไม่มีหมวดอยู่ท้ายสุด

```sql {verify}
SELECT
  category,
  product_name,
  list_price
FROM products
ORDER BY category ASC NULLS LAST, list_price DESC;
```

| category | product_name | list_price |
|---|---|---|
| Beverage | ชาเขียว 500ml | 20.00 |
| Beverage | กาแฟกระป๋อง 180ml | 18.00 |
| Beverage | น้ำดื่ม 600ml | 7.00 |
| Household | กระดาษทิชชู 6 ม้วน | 99.00 |
| Household | ถุงขยะ 30 ใบ | 49.00 |
| Personal Care | แชมพู 400ml | 129.00 |
| Personal Care | สบู่เหลว 450ml | 89.00 |
| Personal Care | ยาสีฟัน 160g | 59.00 |
| Snack | ถั่วอบเกลือ 40g | 30.00 |
| Snack | มันฝรั่งทอด 50g | 25.00 |
| Snack | ขนมปังกรอบ 60g | 15.00 |
| NULL | น้ำยาล้างจาน 500ml | 39.00 |

- `category ASC NULLS LAST` เรียงหมวดตามตัวอักษร และให้ `NULL` อยู่ล่างสุด
- `list_price DESC` ใช้ตัดสิน**เฉพาะเมื่อหมวดเท่ากัน**

> [!DATABRICKS] ตำแหน่งของ NULL โดยค่าเริ่มต้น
> ใน Databricks ค่า `NULL` จะอยู่**บนสุด**เมื่อเรียง `ASC` และอยู่**ล่างสุด**เมื่อเรียง `DESC` (ตัวอย่าง DISTINCT ด้านบนจึงมี `NULL` เป็นแถวแรก) ระบบอื่นอาจต่างกัน ถ้าตำแหน่งสำคัญให้เขียน `NULLS FIRST` / `NULLS LAST` เสมอ

## LIMIT และ Top N

`LIMIT n` ตัดผลลัพธ์ให้เหลือไม่เกิน n แถว ใช้คู่กับ `ORDER BY` เพื่อหา **Top N** ของทั้งตาราง

**สถานการณ์:** ทีมการตลาดอยากเห็นรายการขาย 5 อันดับที่ยอดสุทธิสูงสุด

```sql {verify}
SELECT
  sale_id,
  sale_date,
  store_id,
  net_amount
FROM sales
ORDER BY net_amount DESC, sale_id
LIMIT 5;
```

| sale_id | sale_date | store_id | net_amount |
|---|---|---|---|
| T0022 | 2026-01-09 | S01 | 516.00 |
| T0052 | 2026-01-28 | S01 | 445.00 |
| T0058 | 2026-01-31 | S01 | 435.00 |
| T0096 | 2026-03-02 | S02 | 420.00 |
| T0077 | 2026-02-15 | S03 | 356.00 |

**ลำดับการทำงาน:** ระบบเรียงทั้ง 141 แถวตาม `net_amount` จากมากไปน้อยก่อน แล้ว `LIMIT 5` จึงตัดเอา 5 แถวแรก (`LIMIT` ทำหลัง `ORDER BY` เสมอ)

> [!TIP] รายการอันดับ 4 ผิดปกติ
> T0096 ซื้อน้ำดื่ม 60 ชิ้นในรายการเดียว ซึ่งผิดปกติสำหรับร้านค้าปลีก ก่อนรายงาน Top N ควรตรวจคุณภาพข้อมูลก่อน (บทที่ 19)

## ค่าเท่ากันที่ขอบของ Top N: ใส่ตัวตัดสิน

ถ้าขอ 7 อันดับ จะมีสองรายการที่ยอดเท่ากันที่ 351.00 บาท

```sql {verify}
SELECT
  sale_id,
  sale_date,
  store_id,
  net_amount
FROM sales
ORDER BY net_amount DESC, sale_id
LIMIT 7;
```

| sale_id | sale_date | store_id | net_amount |
|---|---|---|---|
| T0022 | 2026-01-09 | S01 | 516.00 |
| T0052 | 2026-01-28 | S01 | 445.00 |
| T0058 | 2026-01-31 | S01 | 435.00 |
| T0096 | 2026-03-02 | S02 | 420.00 |
| T0077 | 2026-02-15 | S03 | 356.00 |
| T0012 | 2026-01-06 | S04 | 351.00 |
| T0136 | 2026-03-30 | S01 | 351.00 |

ถ้าเขียนแค่ `ORDER BY net_amount DESC` ลำดับของ T0012 กับ T0136 ไม่รับประกัน และถ้าขอ `LIMIT 6` อาจได้คนละรายการในแต่ละครั้ง การเพิ่ม `sale_id` เป็น**ตัวตัดสิน (Tie-breaker)** ทำให้ผลลัพธ์เหมือนเดิมทุกครั้ง

> [!NOTE] ถ้าต้องการ "ทุกรายการที่ยอดเท่ากับอันดับสุดท้าย"
> `LIMIT` ตัดตามจำนวนแถวเสมอ ถ้าต้องการให้ค่าที่เท่ากันได้อันดับเดียวกันและติดอันดับทั้งหมด ให้ใช้ `RANK()` (บทที่ 15) และถ้าต้องการ Top N **ต่อกลุ่ม** เช่น ต่อสาขา ต้องใช้ Window Function (บทที่ 16)

## ข้อผิดพลาดที่พบบ่อย

- คิดว่าข้อมูลเรียงลำดับอยู่แล้วโดยไม่เขียน `ORDER BY`
- ใช้ `LIMIT` หา Top N โดยไม่มี `ORDER BY` ได้แถวสุ่ม ๆ ไม่ใช่ Top N
- ไม่ใส่ตัวตัดสินเมื่อค่าอาจเท่ากัน ทำให้ผลลัพธ์เปลี่ยนไปมา
- เรียงตัวเลขที่เก็บเป็นข้อความ ทำให้ `'100'` มาก่อน `'20'` (ต้องแปลงชนิดก่อน บทที่ 18)
- คิดว่า `ORDER BY` ใน Query จะทำให้ตารางเรียงถาวร (จริง ๆ เรียงเฉพาะผลลัพธ์ครั้งนั้น)

## ฝึกทำ

**โจทย์:** หารายการขาย 3 รายการที่จำนวนชิ้น (`quantity`) น้อยที่สุดของสาขา S01 ถ้าจำนวนเท่ากันให้เรียงตาม `sale_id`

:::answer ดูเฉลยและคำอธิบาย
```sql {verify}
SELECT
  sale_id,
  product_id,
  quantity
FROM sales
WHERE store_id = 'S01'
ORDER BY quantity ASC, sale_id ASC
LIMIT 3;
```

| sale_id | product_id | quantity |
|---|---|---|
| T0061 | P005 | -2 |
| T0001 | P002 | 1 |
| T0002 | P002 | 1 |

**เหตุผล:** เรียง 2 ระดับ: `quantity` น้อยไปมากก่อน แล้วใช้ `sale_id` ตัดสินเมื่อเท่ากัน (มีหลายรายการที่ซื้อ 1 ชิ้น) ผลจึงคงที่ทุกครั้ง แถวแรกเป็นรายการรับคืน (quantity ติดลบ) ซึ่งควรสังเกตไว้
:::
