## WHERE คืออะไร

`WHERE` คือ **เงื่อนไขคัดแถว** ระบบจะตรวจเงื่อนไขกับ**ทีละแถว** แถวไหนเงื่อนไขเป็นจริง (true) จะถูกเก็บไว้ แถวที่เป็นเท็จหรือไม่ทราบค่าจะถูกตัดออก เหมือนการใช้ Filter ใน Excel

**รูปแบบ (Syntax)**

```sql
SELECT column_1, column_2
FROM table_name
WHERE condition;
```

**ลำดับการทำงาน:** ระบบอ่านตารางจาก `FROM` → คัดแถวด้วย `WHERE` → แล้วจึงเลือกคอลัมน์ตาม `SELECT` (รายละเอียดเต็มในบทที่ 13)

## ตัวอย่าง: กรองด้วยเงื่อนไขเดียว

**สถานการณ์:** ผู้จัดการภาคใต้อยากดูรายการขายทั้งหมดของสาขาภูเก็ต (S05)

**ข้อมูลก่อนกรอง:** ตาราง `sales` มี 141 แถว จากทุกสาขา

```sql {verify}
SELECT
  sale_id,
  sale_date,
  store_id,
  net_amount
FROM sales
WHERE store_id = 'S05';
```

**ผลลัพธ์หลังกรอง (7 แถว)**

| sale_id | sale_date | store_id | net_amount |
|---|---|---|---|
| T0093 | 2026-03-02 | S05 | 51.00 |
| T0105 | 2026-03-04 | S05 | 90.00 |
| T0114 | 2026-03-10 | S05 | 79.00 |
| T0122 | 2026-03-20 | S05 | 118.00 |
| T0125 | 2026-03-22 | S05 | 150.00 |
| T0132 | 2026-03-26 | S05 | 85.00 |
| T0133 | 2026-03-28 | S05 | 90.00 |

**สิ่งที่เกิดขึ้น:** ระบบตรวจทั้ง 141 แถวว่า `store_id = 'S05'` หรือไม่ เหลือ 7 แถวที่จริง อีก 134 แถวของสาขาอื่นถูกตัดออก สาขา S05 มีรายการน้อยเพราะเพิ่งเปิดเดือนมีนาคม 2026

> [!KEY] ข้อความต้องอยู่ใน ' '
> ค่าที่เป็นข้อความ (STRING) และวันที่ต้องอยู่ในเครื่องหมาย `' '` เช่น `'S05'` ส่วนตัวเลขเขียนตรง ๆ ได้ เช่น `quantity >= 3`

## ตัวเปรียบเทียบ (Comparison Operators)

| ตัวเปรียบเทียบ | ความหมาย | ตัวอย่าง | เก็บแถวที่… |
|---|---|---|---|
| `=` | เท่ากับ | `store_id = 'S01'` | รหัสสาขาเป็น S01 |
| `<>` หรือ `!=` | ไม่เท่ากับ | `payment_method <> 'Cash'` | ไม่ได้จ่ายเงินสด |
| `>` | มากกว่า | `net_amount > 100` | ยอดมากกว่า 100 (ไม่รวม 100) |
| `>=` | มากกว่าหรือเท่ากับ | `list_price >= 50` | ราคา 50 ขึ้นไป (รวม 50) |
| `<` | น้อยกว่า | `quantity < 0` | จำนวนติดลบ (รับคืน) |
| `<=` | น้อยกว่าหรือเท่ากับ | `quantity <= 1` | ซื้อไม่เกิน 1 ชิ้น |

**ตัวอย่างกับตัวเลข:** สินค้าที่ราคาป้ายตั้งแต่ 50 บาทขึ้นไป

```sql {verify}
SELECT
  product_id,
  product_name,
  list_price
FROM products
WHERE list_price >= 50;
```

| product_id | product_name | list_price |
|---|---|---|
| P007 | สบู่เหลว 450ml | 89.00 |
| P008 | แชมพู 400ml | 129.00 |
| P009 | ยาสีฟัน 160g | 59.00 |
| P012 | กระดาษทิชชู 6 ม้วน | 99.00 |

## กรองช่วงวันที่ให้ครบทั้งเดือน

วันที่เขียนเป็นค่าคงที่ (Literal) ได้ด้วย `DATE'yyyy-MM-dd'` เช่น `DATE'2026-02-01'`

**วิธีที่แนะนำ:** ใช้ `>=` วันแรก และ `<` วันแรกของช่วงถัดไป เรียกว่าช่วงแบบ **ครึ่งเปิด (Half-open)** ข้อดีคือไม่ต้องคิดว่าเดือนนั้นมีกี่วัน และใช้ได้กับคอลัมน์ที่มีเวลา (TIMESTAMP) โดยไม่ตกหล่น

```sql {verify}
SELECT COUNT(*) AS feb_rows
FROM sales
WHERE sale_date >= DATE'2026-02-01'
  AND sale_date <  DATE'2026-03-01';
```

| feb_rows |
|---|
| 30 |

- `sale_date >= DATE'2026-02-01'` ตั้งแต่ 1 ก.พ.
- `sale_date < DATE'2026-03-01'` ก่อน 1 มี.ค. = ถึงสิ้นเดือน ก.พ. ไม่ว่าจะมี 28 หรือ 29 วัน
- `AND` แปลว่าต้องจริงทั้งสองเงื่อนไข (เรียนละเอียดในบทถัดไป)

> [!WARNING] อย่าเขียนวันที่รูปแบบอื่น
> `'14/02/2026'` ไม่ใช่วันที่ในมุมมองของ SQL แต่เป็นแค่ข้อความ ให้เขียน `DATE'2026-02-14'` (ปี-เดือน-วัน) เสมอ เรื่องกับดักของ `BETWEEN` กับข้อมูลที่มีเวลา ดูที่ [กรองช่วงวันที่ให้ครบ](#/formula/f-date-range-filter)

## ตรวจจำนวนแถวก่อนและหลังกรอง

นิสัยที่ดี: นับจำนวนแถวก่อนและหลังใส่เงื่อนไข เพื่อเช็กว่าเงื่อนไขทำงานตามที่ตั้งใจ

```sql {verify}
SELECT COUNT(*) AS row_count
FROM sales
WHERE store_id = 'S01';
```

| row_count |
|---|
| 47 |

ก่อนกรองมี 141 แถว หลังกรองเฉพาะ S01 เหลือ 47 แถว ถ้าได้ 0 หรือได้เท่าเดิม แปลว่าเงื่อนไขอาจผิด

## ข้อความต้องตรงทั้งตัวพิมพ์เล็กและใหญ่

> [!MISTAKE] ค่าข้อความผิดตัวพิมพ์
> ข้อมูลจริงเก็บเป็น `'Cash'` (C ตัวใหญ่) แต่เขียนเงื่อนไขเป็น `'cash'`

```sql {verify}
SELECT COUNT(*) AS row_count
FROM sales
WHERE payment_method = 'cash';
```

| row_count |
|---|
| 0 |

ได้ 0 แถวโดยไม่มี Error ซึ่งอันตรายกว่า Error เพราะอาจไม่รู้ตัว วิธีแก้คือดูค่าจริงก่อนด้วย `SELECT DISTINCT payment_method FROM sales;` แล้วเขียนให้ตรง

```sql {verify}
SELECT COUNT(*) AS row_count
FROM sales
WHERE payment_method = 'Cash';
```

| row_count |
|---|
| 51 |

> [!DATABRICKS] การเปรียบเทียบข้อความแยกตัวพิมพ์
> โดยค่าเริ่มต้น Databricks เปรียบเทียบข้อความแบบแยกตัวพิมพ์ (`'Cash'` ≠ `'cash'`) ต่างจาก SQL Server ที่มักไม่แยก ถ้าไม่อยากให้แยกให้ใช้ `LOWER(payment_method) = 'cash'` หรือ `ILIKE` (บทที่ 5)

## ข้อผิดพลาดที่พบบ่อย

- ลืมใส่ `' '` รอบข้อความหรือวันที่ เช่น `store_id = S01` จะเกิด Error `UNRESOLVED_COLUMN` เพราะระบบคิดว่า `S01` เป็นชื่อคอลัมน์
- พิมพ์ค่าไม่ตรงตัวพิมพ์ หรือมีช่องว่างเกิน
- เขียน `= NULL` เพื่อหาค่าว่าง ซึ่งได้ 0 แถวเสมอ ต้องใช้ `IS NULL` (บทที่ 6)
- กรองวันที่ด้วยข้อความรูปแบบอื่น เช่น `'14/02/2026'`

## ฝึกทำ

**โจทย์:** แสดง `sale_id`, `sale_date`, `product_id`, `net_amount` ของรายการขายสาขา S03 ที่ยอดสุทธิ (`net_amount`) มากกว่า 100 บาท

:::answer ดูเฉลยและคำอธิบาย
```sql {verify}
SELECT
  sale_id,
  sale_date,
  product_id,
  net_amount
FROM sales
WHERE store_id = 'S03'
  AND net_amount > 100
ORDER BY sale_id;
```

| sale_id | sale_date | product_id | net_amount |
|---|---|---|---|
| T0024 | 2026-01-12 | P003 | 108.00 |
| T0076 | 2026-02-15 | P010 | 234.00 |
| T0077 | 2026-02-15 | P007 | 356.00 |
| T0110 | 2026-03-09 | P009 | 118.00 |

**เหตุผล:** รหัสสาขาเป็นข้อความจึงอยู่ใน `' '` ส่วน 100 เป็นตัวเลข ใช้ `>` เพราะโจทย์บอก "มากกว่า" (ไม่รวม 100) และใช้ `AND` เพราะต้องจริงทั้งสองเงื่อนไข
